# data/raw — 수집 원본

여기 넣은 파일은 **커밋되지 않는다** (`.gitignore` 처리).
안내 이미지 자체를 재게시하지 않는다는 원칙(poc-plan 4.4) 때문이다.
가공 결과인 `src/data/events.json`만 저장소에 올라간다.

## 넣는 방법

```
data/raw/
  saengka/     생일카페 안내 이미지·정리글 스크린샷
  popup/       팝업 공식 공지·굿즈 라인업·품절 공지
  links.txt    이미지로 못 담는 링크 (한 줄에 하나)
```

파일명은 아무래도 좋다. 다만 **원문 링크를 알 수 있으면 파일명에 넣거나
`links.txt`에 같이 적어달라** — `source_url`이 필수 필드이고,
화면에 출처를 반드시 노출하기 때문이다.

## 찍을 때

한 장에 여러 건이 들어간 **큐레이션 계정의 주간 정리 이미지가 가장 효율적이다.**
한 장에서 10~20건이 나온다.

이미지에 아래 정보가 보이면 그대로 구조화된다. 없으면 비워두고 넘어간다.

- 대상(아이돌·캐릭터·배우) 이름
- 카페명 / 장소명
- 주소 — **없어도 된다.** 카페명으로 좌표를 찾는다
- 운영 기간 (시작일~종료일)
- 운영 시간
- 특전 (선착 n명 ○○ 등)
- 조건 (음료 1잔 등)

## 팝업은 따로

팝업은 **공식 굿즈 라인업**과 **공식 품절·웨이팅 공지**가 별도로 필요하다.
홍보 훅이 여기서 나오기 때문이다 (poc-plan 8번).

품절 공지는 **게시 시각이 보이게** 찍어달라. `reported_at`에 원문 시각을 그대로 넣고,
`now()`로 찍지 않는 것이 3.1의 핵심 규칙이다.
